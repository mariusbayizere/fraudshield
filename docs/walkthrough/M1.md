# M1 walkthrough — contracts and data model

## What was built

M1 fixes the interfaces and the database before any service exists, so that M5–M8 build against
reviewed contracts and a schema whose security properties are tested.

1. **API contract** (`contracts/openapi/fraudshield-api.yaml`, ADR 0011, ADR 0014):
   - OpenAPI 3.1: 89 operations for ingestion, decisions, staff auth, alerts, accounts, risk
     officer, admin, verification, health and `GET /environment`;
   - RFC 9457 problems from a catalogue;
   - examples for all six channels and a valid example for every object schema;
   - a golden authorisation matrix (`authorisation-matrix.yaml`) that the tests compare with the
     document in both directions.
2. **Event and scoring contracts** (ADR 0012, ADR 0016):
   - 13 Kafka JSON Schemas with committed baselines and a compatibility checker;
   - the scoring protobuf, linted and checked for breaking changes by pinned `buf`;
   - the webhook specification with signature and ordering test vectors;
   - `fs-contract-baselines` guarding branches against incompatible changes to what `main`
     publishes.
3. **Dual control for risk configuration** (`backend/common/.../config`, ADR 0014):
   - tightening applies immediately and needs a second risk officer within 24 hours, or it
     reverts;
   - loosening waits for a different officer; ADMIN can neither propose nor approve.
4. **Database** (`backend/persistence`, ADR 0017, ADR 0018):
   - PostgreSQL 16 + TimescaleDB, Flyway V1–V11;
   - four least-privilege roles;
   - tenant isolation by `institution_id`: RLS on ordinary tables; insert guard plus
     security-barrier views on hypertables, because TimescaleDB forbids compression with RLS;
   - composite foreign keys;
   - append-only tables with grants and owner-proof triggers;
   - a database-assigned SHA-256 audit chain partitioned by transaction time;
   - compression, retention and continuous aggregates.
5. **Demo seeding and the synthetic-data banner** (ADR 0019):
   - `make seed-demo` generates credentials locally and prints them once;
   - the database records that it holds demo data;
   - `SyntheticDataGuard` stops any Spring Boot service outside `dev`/`demo` against such a
     database.
6. **Security documentation**: `docs/security/threat_model.md` (STRIDE per component and data
   flow).

## Key decisions and alternatives

| Decision | Alternative rejected | Why |
|---|---|---|
| Hypertables isolated by insert guard + security-barrier views | RLS on hypertables | TimescaleDB refuses compression on tables with row security; D-32 needs compression |
| Audit chunks and retention by the transaction time `recorded_at` | By the writer's `event_at` | A backdated row could be dropped from the middle of a chain (database review MAJOR-2) |
| Synthetic-data marker in the database, checked by an eager listener | Check only the seeding process's profile, or a lazily created bean | A later `prod` process, lazy initialisation or a missing `JdbcTemplate` bypassed it (review MAJOR-3, PB-15, PB-16) |
| Asymmetric dual control (ADR 0014) | Symmetric approval for every change | Emergency tightening must never wait for a second officer |
| `buf breaking` for protobuf (ADR 0016) | A custom checker | Maintained rule set; the owner asked to replace the custom one |
| EPL-2.0 runtime binaries allowed (ADR 0020) | Replace Spring's logback and Jakarta APIs | Every Spring Boot service needs them; weak copyleft on unmodified binaries is the ASF Category B position |
| MLflow job execution disabled | Raise MLflow's memory limit or retry uploads | Measured root cause of the HTTP 500s; retries or memory would hide it |
| Re-plan D-20, NFR-SEC-03, D-32, D-49 to M6/M7/M9 (ADR 0021) | Close them as done, or keep M1 open | They need components that do not exist yet; the M1 part is recorded as evidence |

## How to run and demonstrate

```bash
make ci                                   # Docker suites skip visibly on the laptop (ADR 0010)
# Database gate without Docker, against any PostgreSQL 16 + TimescaleDB 2.30 superuser URL:
cd backend && FRAUDSHIELD_TEST_POSTGRES_URL="jdbc:postgresql://127.0.0.1:55432/postgres?user=postgres" \
  ./mvnw -B -ntp verify -pl persistence -am
make up && make seed-demo                 # Codespaces or any Docker host; prints demo credentials once
```

A local stack volume migrated before the M1 merge must be recreated (`docker compose down -v`):
V1, V2, V8, V10 and V11 changed before they were merged, and Flyway validates checksums. From the
merge on, `fs-migration-guard` refuses edits to merged migrations.

## What the results mean

- **M1 gate:**
  - `fs_app` gets `42501` for UPDATE, DELETE and TRUNCATE on `audit_events`, `auto_block_events`
    and `alert_decisions`.
  - Each institution sees and writes only its own rows; without a tenant it sees and writes
    nothing.
  - The OpenAPI document validates against 3.1.
  - Mutation checks show each gate test fails when its property is broken.
- **Audit chain:** tampering, gaps and a head ahead of the stored rows are reported. Retention can
  only remove a prefix of a chain, shown with 1-second chunks in the database re-check.
- **MLflow:** at its 1 GiB limit before the fix (peak = limit, 4,000+ limit events). After it, 38%
  anonymous memory, 0 limit events and 0 OOM kills, guarded by the smoke test.
