# M0 walkthrough — bootstrap and governance

## What was built

M0 builds the frame that makes every later claim checkable. There is no fraud model or service
yet.

1. **Requirements as data.** The SRS `.docx` is extracted to `docs/srs/FraudShield_SRS_v1_0.md`.
   `tools/src/fraudshield_tools/traceability_seed.py` parses its tables into
   `docs/traceability/requirements.yaml`: 60 functional requirements, 147 rows from the
   non-functional, UX, mobile, ML, CI, observability, testing and research tables, and the 51
   defect resolutions — 258 rows in total.
2. **Defect register.** `docs/srs/defect_register.md` is generated from Part B of the build
   prompt, so it cannot drift from the binding resolutions.
3. **Enforcement.** `fs-traceability-seed --check` fails if any SRS-derived field or row in
   `requirements.yaml` differs from a fresh seed. `fs-traceability check` (CI job `governance`)
   fails when a test tag names an unknown requirement; a completed row lacks a tagged test or has
   evidence that is not an existing path, commit or CI run; a deviation is not an existing ADR; a
   row uses a non-test verification method it was not granted; or a closed milestone still has
   open Must rows (ADR 0004). `fs-scope-guard` fails if vocabulary from the unrelated project
   copied into SRS section 05B appears outside reviewed exemptions (D-47, ADR 0008).
   `fs-licences` enforces the dependency licence policy (ADR 0009) and `fs-commit-msg` the commit
   standard.
4. **Toolchain.** Versions were checked against upstream support on 2026-09-17; unsupported
   SRS versions were replaced with ADRs (ADR 0003): Spring Boot 4.1.1, React 19, MUI 9,
   TypeScript 6.0, Redis 7.2 (last BSD-licensed line), SeaweedFS instead of the archived MinIO
   (ADR 0005).
5. **First real code in each language**, chosen because later milestones depend on it:
   - Java `common`: `Money` / `CurrencyCode` — exact `DECIMAL(18,4)` amounts and ISO 4217 minor
     units, cross-checked against the JDK's ISO data (D-43).
   - Python `fraudshield_ml.metrics.operating_points`: the precision ceiling at a fixed FPR
     (D-01) and the precision/FPR implied by recall and F1 targets (D-02).
   - TypeScript `contrast.ts`: WCAG relative luminance and contrast ratio; tests re-measure
     every ratio quoted in D-33.
6. **Local stack** (`docker-compose.yml`, profile `core`) and **CI** (`.github/workflows/ci.yml`).

## Key decisions and alternatives

| Decision | Alternative rejected | Why |
|---|---|---|
| Progressive traceability enforcement by milestone | "Every Must row has a test" from day one | Would keep `main` red until the last milestone |
| Generate rows and register from source documents | Retype them by hand | Retyping drifts silently; generated files are checked for staleness in CI |
| Move to supported framework versions with ADRs | Keep SRS-named versions | Spring Framework 6.2, React 18 and MUI 5 no longer receive fixes |
| Money minor units held in code, tested against the JDK | Read from `java.util.Currency` at runtime | Display rules must not change with a JDK upgrade |
| Random local credentials generated into `.env` | Committed default passwords | No secrets in git, even for development |

## How to run and demonstrate

```bash
make bootstrap
make ci                  # all lint, type, unit and governance checks
uv run fs-traceability check
make up && make smoke    # needs Docker: run in Codespaces (ADR 0010)
```

## What the results mean

- Precision at 1% FPR cannot exceed **0.4674** at a 0.87% fraud rate (unit test), which is why
  the SRS gate of 0.720 is replaced by recall at 1% FPR (D-01).
- Recall 0.88 with F1 0.80 implies precision **0.7333** and FPR **0.28%** at the flag threshold
  (unit test), confirming D-02's consistency figures.
- All eleven contrast ratios quoted in D-33 reproduce to two decimals; the five SRS pairings
  fail WCAG AA for normal text and the six replacement tokens pass.

## Where Docker runs (owner decision, ADR 0010)

Docker does not run on the author's laptop. The container stack is verified by the CI `stack` job
(`make up --wait` and `make smoke`); M0 requires three consecutive green runs plus a green run on
the merged head, recorded in `docs/reviews/M0/stack-gate-evidence.md`. For interactive Docker work, open the repository
in GitHub Codespaces (4 cores / 16 GB); the devcontainer installs everything and runs `make ci`.
Locally, `make ci` prints `SKIPPED: … requires Docker, verified in CI` for Docker suites.
Performance gate numbers will come from a dedicated machine recorded in
`docs/benchmarks/hardware.md`, never from CI runners.
