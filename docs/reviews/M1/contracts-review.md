## Residual risks

- **M1 is not complete.** These branches cover only the contract half of M1. The Flyway data model, RLS,
  the `fs_app` INSERT/SELECT-only grants and the M1 gate DB security tests are not reviewed here. They are
  Docker-dependent and must be verified in CI.
- **No WebSocket/STOMP message contract.** The alert feed (FR-04-02), escalation notifications
  (FR-04-10) and retraining progress (FR-06-04) cross Java→TypeScript with no schema. This is a drift
  risk before M8.
- **Contracts are not yet consumed by code.** No Java or TypeScript is generated from the OpenAPI or proto,
  so conformance is unproven until M5–M8 add generated-code and controller conformance tests. CR-01
  shows why a response-conformance test is essential.
- **Audit durability.** `fs.audit.events` keeps P7D before the hash-chained append. An audit-writer
  outage longer than 7 days loses audit events unless the outbox, not Kafka, is the source of truth.
- **Quasi-identifiers.** `fs.transactions.scored` carries exact latitude and longitude with account tokens,
  and its consumers include `analytics`. Record this in the DPIA (D-22) and consider coarsening for
  non-scoring consumers.
- **Insider collusion.** Even with CR-04 and CR-05 fixed, two ADMINs (or an ADMIN creating a sock-puppet
  RISK_OFFICER) can bypass separation of duties. Account creation and role grants may need dual control.
- **Evidence limits.** CI evidence came from the unauthenticated GitHub API (job conclusions only, logs not
  inspected). Docker-dependent suites were not run locally (ADR 0010).
