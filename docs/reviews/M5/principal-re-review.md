## Residual risks

- **Finding 2's second half was not implemented.** `_resolve_account` (`store.py:536-560`) still consults the fallback only when `a:*:first` is missing, and a read with `prof`/`tier`/`swap` gone is not degraded. Probe on a production-shape store (`authoritative=False`, keys deleted after an `observe`): `account_age_days set: False  kyc_tier set: False  days_since_sim_swap set: False  degraded: False  fallbacks: 0.0`. The TTL alignment makes this unreachable by expiry, but a Redis eviction under `maxmemory`, a partial restore, or a `set_kyc_tier` that never ran still produce a feature-poor score the API is told is healthy.
- **The in-process `Comparison`'s shadow series is unasserted.** Mutation 11 fed it production's score twice (`shadow.py:369`) and `test_shadow.py` + `test_server.py` stayed green (`24 passed`). That deque is what `Comparison.metrics()` turns into `shadow_psi` and `shadow_mean_abs_score_diff` (`shadow.py:154-162`) and what `MlflowComparisonLog.flush` writes. A defect of exactly the shape finding 6 named would show operators perfect agreement between two different models and nothing would catch it.
- **`_warm` widened an unprotected region.** `AliasWatcher.poll_once` calls `self._on[alias](bundle)` at `registry.py:409`, *outside* the `try/except (RegistryError, BundleError, OSError, ValueError)` that guards the fetch and load. Probe: a `RuntimeError` from `Bundle.raw` escapes `poll_once`, increments neither `fs_model_swaps_total` nor `fs_model_swap_failures_total`, and leaves `loaded` at `{'production': None, 'shadow': None}`. In `AliasWatcher.start()`'s `loop()` (`registry.py:416-421`) that kills the daemon `alias-watcher` thread, so the worker silently stops hot-swapping for the rest of its life while gRPC health stays `SERVING` on the old model. The region existed before, but the fix moved an ONNX session build and a full inference into it — the most failure-prone thing in the swap path, and precisely what the residual risk was about. This is the weakest of the new problems (it needs an ORT failure to trigger) so I have not raised it to a numbered finding, but wrapping `self._on[alias](bundle)` in the same `except` and counting a failure would cost one line.
- **`FR-02-09`'s row text is a proposal, not a fact.** `requirements.yaml:300-308` has no `status` and no `notes`; the measured skew lives only in `M5_updates.md:509-525`. If the owner merges without applying §15, FR-02-09 renders `NOT_STARTED` with no mention of the skew and no link to ADR 0034. The condition is satisfied only conditionally on the owner's own merge step.
- **`pytest-timeout` is still absent** (`ModuleNotFoundError: No module named 'pytest_timeout'`), so the earlier review's mutation-3 hang remains a way for a regression to stop CI rather than report.
- **ADR 0034's own extra recommendation was half-built.** The metric landed (bb4ece4); the "startup log line naming the producers that are absent" did not — `grep -rn "producer" ml/src/fraudshield_ml/serving/` finds only shadow-sink code. An operator starting a worker gets no notice that four trained features will be constants.
- **`fs-bench memory` still constructs `Scorer(Bundle.load(...), Reference.from_packs(...))` without thresholds** (`benchmark.py:395`), falling back to `ThresholdStore(None)` → `DEFAULT` → `anomaly_review=0.70` (`scorer.py:67`). Harmless for a memory benchmark, but it is the last place 0.7 is reachable without asking for it.
- **Carry 2 is a placeholder with an acceptance test.** `M6_updates.md:183-203` correctly says no topic exists and names the store's write seams and the as-of rule, but it specifies no topic name, no schema fields and no producer, so an M6 or M9 agent cannot start building — only start designing. Carry 1, by contrast, is genuinely executable as written: it names the function, the event, the two features to assert on, the leakage case and the metric to watch. That asymmetry is honest but means the larger half of the BLOCKER is carried as an intention.
- **`requires_docker` evidence and the M6 `Fallback`** remain as the earlier review left them: the Redis 7.2.16 parity replay, the real-MLflow swap test and the PostgreSQL fallback have never executed on any machine visible from here.
