## Residual risks

- **Shadow scoring shares the worker's GIL.** `ShadowRunner` runs in a thread inside the scoring process (`shadow.py:322`), so under load the shadow model's feature computation and SHAP compete for the GIL with production requests. "Never slow … a production decision" holds for blocking, not for CPU. No benchmark in `docs/benchmarks/` was run with shadow enabled; FR-02-07's numbers are shadow-off.
- **First request after a hot swap pays the ONNX session build.** `Bundle._sessions` is a `functools.cached_property` (`bundle.py:191`) built on the first `raw()` call, after the swap has already been published, and `cached_property` is unsynchronised, so concurrent first requests may each build a session. "Fully resident before the swap" is not quite true for the inference sessions.
- **Hot-path Redis timeout is 1 s** (`server.py:243`) against a 40 ms budget; one slow store read stalls a worker thread for 25 budgets before answering `UNAVAILABLE`.
- **A failing test can hang instead of failing.** Mutation 3 hung the blue-green test indefinitely; `pytest-timeout` is not installed, so a regression of that shape stops CI rather than reporting.
- **The manifest itself is not hash-protected** (`bundle.py:260-275`): per-file SHA-256 lives in the manifest, so the ECE the promotion block reads and the file hashes are both self-reported by whoever can write the registry. Acceptable only with registry write ACLs (M9).
- **`requires_docker` evidence.** As the author records (M5-1), the Redis 7.2.16 parity replay and the real-MLflow test have never executed; fakeredis and the fake MLflow encode one reading of those servers.
- **DB fallback (author's M5-3) remains a protocol only**, and with ADR 0033 the scorer, not the API, now owns C.4's "Redis down → DB fallback"; today a store failure is `UNAVAILABLE` and an expired key is a degraded, feature-poor score.
